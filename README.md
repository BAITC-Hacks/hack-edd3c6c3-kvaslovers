# Career Quest

Веб-приложение хакатона HackAlem AI: профиль и карьерная траектория,
объяснимые рекомендации, сохранение прогресса и закрытый HR-обзор.
Исходное оформление команды сохранено; демонстрационные значения заменены
данными из стартового kit и ответами API.

## Запуск одной командой

Нужен Python **3.9+** с SQLite (обычная установка Python). Внешних Python-пакетов,
Node.js, сборки frontend и ключей облачных сервисов для основного сценария не нужно.

Из корня клонированного репозитория:

```bash
python3 -m Backend.main
```

Откройте **http://127.0.0.1:8000**. Не открывайте `index.html` как файл.
На Windows вместо `python3` можно использовать `py -3`.

При первом запуске создаются локальная база `.local/career_quest.sqlite3`
и случайные учебные пароли в `.local/credentials.json`. Откройте этот файл
в VS Code либо выполните в другом терминале:

```bash
cat .local/credentials.json
```

Доступы:

- `hr`: все профили, HR-аналитика, импорт проверочных данных;
- `E0002`, `E0004`, `E0151`: каждый видит только свой профиль и историю.

Логины не являются паролями. Пароли не прописаны в коде и не отправляются в Git.
Исходный dataset не изменяется. Прогресс сохраняется после перезапуска сервера.
Сессии истекают через 8 часов и не сохраняются после остановки сервера.

На странице входа можно создать учётную запись сотрудника и выбрать свободный
профиль. Один профиль связан только с одним аккаунтом. Для регистрации HR
задайте `CAREER_QUEST_HR_REGISTRATION_CODE` до запуска и используйте это
значение как код приглашения. Без кода доступны только уже созданный локальный
аккаунт HR и регистрация сотрудников:

```powershell
$env:CAREER_QUEST_HR_REGISTRATION_CODE = "private-invite-code"
py -3 -m Backend.main
```

Пароли новых пользователей сохраняются в SQLite как salted PBKDF2 hashes;
сами пароли не попадают в базу. Новые логины остаются после перезапуска.

Для отдельного чистого прогона без удаления текущего прогресса:

```bash
python3 -m Backend.main --port 8001 --db .local/rehearsal/state.db
```

Это отдельная база и отдельный файл паролей `.local/rehearsal/credentials.json`.
Сервер слушает только localhost. Это локальный хакатонный стенд, не production
развёртывание с SSO/TLS; публичный доступ не включён.

## Сценарий защиты

1. Войти как `E0002`: Middle → Senior, покрытие требований **62%**.
2. Показать `System Design Fundamentals` (EV_005, score **0.6120**):
   два критических навыка, API Design и System Design, **1 → 2**, требуется **4**.
   Раскрыть «Как рассчитана оценка»: критичность, разрыв, эффект и история.
3. Нажать «Отметить выполненной»: покрытие становится **66%**, появляется
   запись истории; новые рекомендации учитывают достигнутые уровни.
   Обновить страницу — изменения сохраняются. Повторный HTTP-запрос не
   начисляет прирост повторно.
4. Выйти и войти как `hr`. Открыть «Обзор команды»: дефициты навыков,
   сотрудники без шага, отсутствие добровольных завершений за 90 дней,
   участие по всем 40 активностям и всем статусам.
5. Загрузить `docs/jury-sample/employees.json` и
   `docs/jury-sample/activity_history.csv` через форму HR. Можно также
   вставить их содержимое в текстовые поля. Открыть импортированные профили:
   - `JURY_A`: три неявки Public Speaking, но критичен System Design;
     ожидаемый TOP-3: EV_006, EV_005, EV_007;
   - `JURY_B`: переход Data Analyst → Product Manager;
     ожидаемый TOP-3: EV_026, EV_021, EV_027;
   - `JURY_C`: требования закрыты, корректное пустое состояние.
6. Проверить приватность: в аккаунте сотрудника нет HR-вкладки и выбора
   чужих профилей; прямой запрос к чужому ID также возвращает 403.

Ещё три исходных примера: `python3 -m ai.demo`, сценарий в `ai/demo/README.md`.
CLI читает исходный kit, веб-приложение — сохранённую SQLite-базу. После
отметок о выполнении веб-результаты закономерно отличаются от исходного CLI.

## Как работает расчёт

Чистая функция `ai.recommendation.recommend` выбирает 0–3 доступных события.
Проверяются роль/грейд, prerequisites, будущая сессия, обязательность,
завершения и текущие участия. Полезный прирост ограничен `gain`, `max_level`
и оставшимся разрывом. Критичность, разрыв, эффект и история имеют веса
0.35/0.30/0.20/0.15. Это прозрачный алгоритм по правилам, а не обученная модель.
Подробная схема, формула и интерфейс: [ai/README.md](ai/README.md).

Доля покрытия траектории = сумма `min(текущий, требуемый)` по целевым навыкам /
сумма требований × 100. Это не вероятность повышения, а покрытие требований.
Прогнозируемый прирост не записывается до добровольной отметки о выполнении.

Правила учебного стенда:

- Время фиксировано на дате kit **2026-10-01**. Кнопка выполнения моделирует
  результат на эту дату, даже если предложенная сессия позже; это явно подписано.
- Завершения после последней оценки сначала учитываются в фактических уровнях.
  При новом выполнении материализуется полный снимок навыков и переносится
  граница снимка (`skill_snapshot_date`). Дата реальной оценки сохраняется; исторические приросты не учитываются дважды.
- Повторный клуб EV_036 разрешён, но один зачёт на дату среза. Прочие
  добровольные активности после завершения не повторяются.
- Явная карьерная цель имеет приоритет над следующим грейдом своей роли.
  Для Lead без цели используются требования Lead. Это решения продукта,
  а не обещания о реальном повышении.
- Для self-paced в исходном CSV нет даты завершения: используется доступная
  дата записи, что ограничивает точность восстановления старых уровней.
- Пустой список допустим, если подходящих мероприятий нет. HR отдельно видит
  таких сотрудников. Нерелевантные активности не добавляются ради количества.

## Импорт жюри

Доступен только HR. Можно загрузить весь совместимый набор: `employees.json`,
`events.json`, `skills.json` и `activity_history.csv`. JSON отправляется как
объекты, CSV — текстом внутри запроса. Также поддерживается частичное добавление
профилей и истории для сценариев жюри. UI принимает файлы или вставленный текст,
но не оба источника одного типа одновременно.

Новые employee_id добавляются, существующие профили обновляются; история
объединяется по record_id. Повторная загрузка одинаковых записей безопасна.
При полной загрузке каталоги событий и навыков заменяются переданными версиями,
но только если дата среза совпадает и новые каталоги совместимы с уже сохранёнными
профилями, навыками, целями и историей. Данные применяются одной транзакцией;
пользователи и записанный прогресс не удаляются.
Конфликтующий record_id, неизвестная роль/навык/событие, неверный уровень,
статус или дата отклоняют **весь** импорт с 422, без частичных изменений.
Дата meta должна совпадать со срезом. Лимит запроса 4 MB, до 1000 профилей и
20000 записей за импорт. Профиль с уже сохранёнными выполнениями нельзя
перезаписать другим снимком — используйте новый ID для проверочного профиля.
Новые профили доступны HR; импорт не создаёт учётные записи и не даёт права HR.

## API и интеграция

Все данные требуют cookie-сессию; исключения — статические файлы и `/health`.

| Метод | URL | Назначение |
| --- | --- | --- |
| POST | `/api/login` | `{username, password}` → user и csrf; HttpOnly cookie |
| GET | `/api/registration/profiles` | Свободные employee-профили для регистрации |
| POST | `/api/register` | Создать учётную запись с ролью employee/HR |
| GET | `/api/me` | Текущая сессия, csrf и дата среза |
| POST | `/api/logout` | Отзыв сессии |
| GET | `/api/employees` | HR: расширенный список всех; сотрудник: только свой профиль |
| GET | `/api/employees/{id}` | Профиль, траектория, история, рекомендации |
| GET | `/api/employees/{id}/history` | История участия этого сотрудника |
| GET | `/employees/{id}/recommendations` | Совместимый endpoint движка; также с префиксом `/api` |
| POST | `/api/employees/{id}/complete` | `{event_id}` → изменения, прогресс до/после, новый профиль |
| GET | `/api/hr/summary` | Активность, средний прогресс, completion rate, дефициты, рекомендации и отсутствие активности |
| POST | `/api/import` | `{employees, history}`; history — CSV-строка или массив записей |
| POST | `/api/datasets/upload` | Полный набор `{employees, events, skills, activity_history}` |
| POST | `/api/employees/{id}/explanations` | Опциональная локальная LLM с fallback |

POST требует JSON и `X-CSRF-Token` из ответа login/me, кроме самого login.
401 — нет сессии; 403 — чужой профиль/HR/CSRF; 404 — неизвестный ID;
409 — недоступное выполнение; 422 — ошибка данных. Ошибки имеют `{error: ...}`.
Для сотрудника неизвестный чужой ID возвращает 403, не раскрывая существование
чужого профиля; HR для неизвестного ID получает 404.

## Локальная LLM (опционально)

Факторы и исходные объяснения работают без LLM. Добавлен реальный HTTP-адаптер
к локальному Ollama `127.0.0.1:11434/api/generate`, согласно
[официальному API](https://docs.ollama.com/api/generate). Если Ollama уже
установлена и модель загружена, задайте имя вашей локальной модели:

```bash
CAREER_QUEST_OLLAMA_MODEL=your-local-model python3 -m Backend.main
```

Кнопка «Дополнить объяснение локальной LLM» передаёт только выбранные события,
навыки и агрегированную историю, без имени/ID сотрудника. Облачного API нет.
На весь запрос отведено до 7 секунд; ошибка/некорректный ответ/тайм-аут оставляют
детерминированное объяснение. LLM-текст подписан как дополнительный и не
меняет оценки или навыки. Тесты проверяют протокол адаптера и fallback;
живой вывод модели на машине без Ollama не проверен. Базовый рекомендатель
не выдаётся за работающую LLM. Уточнение необходимости конкретной модели
остаётся вопросом трактовки AI-слоя организаторами.

## Проверка и структура

```bash
python3 -m unittest discover -v
```

Проверяются 200 исходных профилей, сложные случаи ранжирования, права, HTTP API,
регистрация employee/HR, история, загрузка четырёх файлов и права; также
транзакции, одновременное выполнение, перезапуск базы, импорт/откат, HR-агрегаты
и fallback модели. Тестовые базы создаются во временных папках.

```text
ai/                 Движок, объяснения, траектория и неизменённый kit
Backend/main.py     HTTP, сессии, права, API, локальная раздача frontend
Backend/store.py    SQLite, выполнение, импорт, HR-агрегаты
index.html          Вход, профиль, рекомендации, HR и импорт
app.js, styles.css  Интерфейс команды, подключённый к API
tests/              Интеграционные тесты
.local/             Состояние и доступы конкретного запуска; игнорируется Git
```

Матрица требований и результаты проверки: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).
Данные синтетические, используются только внутри хакатона. Сервер не раздаёт
исходный dataset, SQLite или файл доступов. Нет публичного рейтинга сотрудников,
баллов за обязательные процессы или использования реальных персональных данных.
Геймификация, награды и остальные пункты раздела «Опционально» не входят в
обязательный сценарий и не реализованы.

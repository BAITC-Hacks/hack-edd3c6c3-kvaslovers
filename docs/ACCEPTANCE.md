# Проверка обязательных требований Career Quest

Источник: раздел «КЕЙС: CAREER QUEST» пользовательского PDF HackAlem AI,
русская версия, страницы 3–6. Проверка: 2026-09-23, дата данных 2026-10-01.
Границы: обязательные пункты и ограничения. Перечисленные в ТЗ опциональные
награды, календарь, прогноз оттока и другие расширения не заявляются готовыми.

| Требование | Реализация | Проверяемое свидетельство |
| --- | --- | --- |
| Профиль, роль, грейд, навыки, прошлые активности | GET profile, экран «Мой рост» | Вход E0002, полная история и фактические уровни; браузерная проверка |
| Карьерная траектория и следующие шаги | ai/profile.py, покрытие требований, до трёх карточек | Исходный E0002: 62%, Middle → Senior |
| Рекомендации по нескольким факторам | ai/recommendation.py + scoring.py | 18 тестов движка, все 200 профилей; дополнительные JURY_A/B/C |
| Объяснение минимум по трём факторам | Цель/грейд, разрыв/требование, прирост и история; структурированные contributions | Карточка EV_005: 0.35 + 0.18 + 0.032 + 0.05 = 0.612 |
| Выполнение → обновлённые навыки и траектория | POST complete, SQLite, снимок навыков | HTTP-тест: рост покрытия, новая история, повтор и параллельные запросы без повторного прироста; повторное открытие БД |

## Финальная проверка 2026-09-23

Объединённая версия: движок, защищённая регистрация по персональному приглашению,
импорт четырёх файлов и интерфейс с единым API. Финальный unittest-прогон: **34 теста, OK**, 2.396 с;
HTTP: профиль 0.0014 с, HR 0.0366 с, рекомендации 0.0010 с на этой машине; команды: `python3 -m unittest discover -v`,
`python3 -m ai.demo`, `node --check app.js`, `git diff --check`.

В браузере на отдельной чистой базе проверены вход E0002, выполнение EV_005
с прогрессом 62% → 66%, сохранение после перезагрузки, раскрытие навыков,
вход HR, поиск E0002 и импорт нового JURY_FINAL с тремя no_show.
HTTP-тесты проверяют перезапуск базы, повторные/параллельные выполнения,
права, приглашения и атомарность импорта. Импорт через выбор файла и работа
с другого физического устройства отдельно не проверялись.

## Критерии оценки из ТЗ

| Критерий | Максимум | Подтверждение и границы |
| --- | ---: | --- |
| Соответствие задаче и работоспособность | 25 | Профиль → рекомендация → выполнение → прогресс; HR и импорт |
| Техническая реализация | 25 | Многофакторный Python-движок, SQLite, сессии, права, атомарные изменения; обученной модели нет |
| README и воспроизводимость | 25 | 11 разделов, одна команда запуска, пароли, команды тестов и сценарий жюри |
| Ценность и применимость | 15 | Связь активности с карьерной целью и обзор дефицитов; влияние на бизнес не измерялось |
| Потенциал и оригинальность | 10 | Смена роли, учёт истории, прозрачные вклады; локализация и production deployment остаются развитием |

Это сопоставление с критериями, не прогноз выставленных баллов.
В ТЗ указано 1–3 рекомендации; при отсутствии допустимых событий выдаётся 0.
Это явное продуктовое решение, чтобы не добавлять нерелевантные мероприятия.
На исходном kit 32 из 200 профилей не имеют доступного шага; HR видит их отдельно.
Опциональные геймификация, календарь и локализация EN/KZ не заявляются готовыми.

## Что не следует заявлять на защите

- Алгоритм не обучен на бизнес-результатах; веса — объяснимая эвристика.
- Локальная LLM интегрирована по HTTP, но не установлена на этой машине.
  Успешный ответ, транспортный формат, ошибка и deadline проверены тестами;
  живой вывод настоящей модели не проверен. Без неё работает алгоритм по правилам.
- Синтетический учебный стенд не является production банковской системой:
  нет корпоративного SSO, TLS-терминации и внешнего развёртывания.
- Выполнение — симуляция на фиксированной дате kit, а не подтверждение
  реального присутствия на будущей сессии.
- Доля покрытия навыков не является вероятностью или гарантией повышения.
- Профили жюри ещё неизвестны; проверены дополнительные собственные профили
  той же схемы, а не скрытый оценочный набор организаторов.

## Данные и внешние сервисы

Исходные данные остаются в локальном приложении/командном репозитории хакатона.
Сервер выдаёт только разрешённый конкретному пользователю API, а не каталоги
файлов. Секреты и БД исключены из Git. LLM-адаптер ограничен localhost,
облачные отправки не выполняются. Исходные файлы kit сохранены без изменений.
